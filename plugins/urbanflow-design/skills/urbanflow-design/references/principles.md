
# Urbanflow design principles

The shared rulebook every other `urbanflow-design` skill loads. Urbanflow is a **browser-based building-performance platform** (desktop web). Architects and sustainability consultants draw or import a massing model, assign archetypes and space uses to floors and zones, then run simulations for energy, embodied carbon, cost and compliance — comparing schemes side by side before the design is fixed. Current commercial focus: existing-building retrofits (calibration → recommendations).

> **Status (1 Oct 2026): the DS is mid-rebuild as the Flow Design System.** Foundations (colour, type, spacing, radius, shadow, icons) **and components** (the Components page, the **Shell** page — shared app chrome for Urbanflow and Flux — plus the ↪ Compliance, ↪ Comments and ↪ Files feature pages) are in the Flow Figma file and mirrored in its Design System artifact. Use Flow components first; fall back to the Claude Design components only for something Flow doesn't have yet, and flag it. Components and variables will keep changing. Items marked **TO BE UPDATED** are placeholders, never rules. When a live source disagrees with this skill, the live source wins — say so in one line.

## 1. Non-negotiables

- **Tokens only.** In Figma bind the Flow variables and styles (`TextIcons/Primary`, `spacing/16`, `radius/lg`, `header/small`, `Shadow/sm`); in notes write `token (value)`. No raw hex, px radii or shadows.
- **Type:** Figtree for all UI. **DM Mono only for numbers** — `metric/*` for readouts, `metric/xsmall` (16, the smallest) for compact values in tables — never prose. Styles: `header/*` SemiBold, `label/*` SemiBold (UI text: buttons, inputs, tabs, table headers), `paragraph/*` Regular, `metric/*` DM Mono Regular. Tracking 0. Titles in `TextIcons/Emphasis`; section headings may use `TextIcons/Tertiary` only at 24px+ (contrast).
- **Warm-paper neutrals everywhere; colour only for** links, focus, status, errors and AI (magic). Ink is `#202020` at 100/80/70/50/40/30%.
- **Buttons (Flow Button `1712:13271`):** `primary` = `Background/Inverse` (#1A1A1A) with `TextIcons/InversePrimary`; `secondary` (default) = `Background/Default` with a `Stroke/default` ring; `tertiary` = ghost, `Background/Light` on hover; `plain` = link text `TextIcons/LinkPrimary`. Tones `critical` (destructive) and `success` (approve). Sizes micro 24 · medium 28 · large 32; label `label/xsmall`; `radius/md`. One primary per view; blue is never a button fill.
- **Radii (Flow `radius/*`):** none 0 · xs 2 swatches · sm 4 checkboxes, colour indicators · md 8 buttons, inputs, selects, tabs, badges, action lists, toasts, tooltips · lg 12 cards, modals, banners, hybrid button groups · full pills, chips, toggles, avatars. **Flow has no 16px radius** (the Claude Design components use 16) — use `radius/lg` and flag the drift.
- **Spacing (Flow `spacing/*`):** 0 · 2 · 4 · 6 · 8 · 12 · 16 · 24 · 32 (no 20). Panel padding 16; card padding 8 or 16; gaps inside controls 2–8.
- **Strokes are inset box-shadows** (never change layout): subtle #ECECE6 dividers in a card, default #E3E3DC card/input borders, strong #D1D1CA on hover.
- **States:** hover and press move **one step**; no scale, no bounce. Focus = 2px `Semantic/info-primary` ring (Flow effect `[hack] shadow-focus`), never colour alone. Motion 80–180ms `cubic-bezier(0.2,0,0,1)` on colour and shadow only. Toasts auto-dismiss after 4s.
- **Cards:** `radius/lg`, `Stroke/default` or `Stroke/subtle` ring, `Shadow/sm`; selectable cards (Output Select) hover to `Background/Light` + `Background/Inverse` ring and select to `Semantic/info-xxxlight` + `Stroke/selected`. Status on the **ring only** (green complete + tick, amber active, near-black selected); locked dims to 45%. **No coloured left borders, no tinted card fills.**
- **Icons:** the in-house Flow set (Figma Icons frame; SVGs in the Flow artifact) at the optical size that fits (14 tree rows / micro buttons, 16 menus and controls, 20 toolbars and panel headers). **Default icon colour is `TextIcons/Placeholder`** (40%, changed 1 Oct 2026 — 2.43:1, below 3:1), so every icon-only control needs a label/tooltip; selected or primary controls use their own ink (`TextIcons/Emphasis`, `TextIcons/InversePrimary`). When Flow has none, take one from **Tabler** (outline) or **Phosphor** (regular/semibold) at 1.5px stroke at 20 and keep it local during exploration. Add it to the Flow Icons page as `Size=20/16/14` only after explicit approval or an explicit library-update request. Never Lucide/Heroicons, emoji or unicode glyphs. `currentColor` only.
- **Imagery is data only** (massing renders, site aerials). No gradients, stock photos, illustrations, or people. Use grey placeholders if none is supplied.
- **Brand:** circular black U/F monogram (`urbanflow-design-build/assets/urbanflow-logo.png`, vector `assets/logos/urbanflow-mark.svg`; white `assets/logos/urbanflow-mark-white.svg` for the dark top bar; also in the Flow artifact's Logos group). Flux's mark: `assets/logos/flux-mark-white.svg`. 16px in the top bar, 24–26px elsewhere. Never redraw or recolour it. No wordmark artwork — set "Urbanflow" in Figtree Bold 20px, −0.2px tracking.
- **Stay off:** Figma tooling families (Label*, Annotation*, `.token`, Figma-Tools, Design-only), deprecated families, the Radii frame titled "Do not implement", Background-new (ignore), old TextIcons/Stroke.

## 2. App shell (desktop, design at 1440×1024 in Figma; 1440×900 for prototypes)

Every product uses **AppShell** (Figma Shell `6085:5003`, `Product` = Urbanflow | Flux) — one skeleton, product-specific content, like Figma Design / Slides / FigJam. Start from the appropriate AppShell, then detach it before customization. Put screen-specific content directly into the detached structure, never into AppShell slots. Apply this to every screen, not only AI; preserve nested Flow instances and verify content survives. The regions below describe the shell anatomy, not permission to populate slots in Figma:
- **Top bar** — `.TopNavigation` (44px, `Background/Inverse-Secondary`): product logo + **UrbanflowTopNav** (project switcher menu, open proposal with ProposalTitle/ProposalBadge, notifications, collaborators, credits). Flux hides notifications and collaborators.
- **Canvas** slot — full-bleed behind the panels (`Background/Light`): render, map or board.
- **Left panel** / **Right panel** slots — hug width, fill height, float `spacing/8` inside the canvas (`Show left panel` / `Show right panel`). Urbanflow: LeftContextPanel `Product=Urbanflow` (252px) + analysis panel (ContextPanel 359). Flux: LeftContextPanel `Product=Flux` (360px, chat in its `Panel content` slot) + model panel (~300). The left panel opens at its default width every session and is resizable by dragging its edge; widths are never saved.
- **Canvas tools** slot — floating tools pinned by constraints: **UtilitiesToolbar** top-right (Urbanflow analysis tools; **Flux modes Model · HVAC · Weather · Runs · Results · Files** — modes never go as tabs in the top bar), bottom-centre toolbar, bottom-right view switcher (Massing/Floor plan, 3D/2D).

Other screens (Projects home, Analysis, Comparison, onboarding) reuse the same components. Build screens from Flow components (BuildingSelect / BuildingHeader tree, PageHeader, FullScreenModalHeader, IconButtonGroup and HybridButtonGroup over the canvas); the Claude Design **Platform template** is a layout reference only.

## 3. Voice (read off the product — don't invent a new one)

Flat, instrumental, engineer-to-engineer — "a precision instrument". Labels are 1–3-word nouns ("Floor height", "Wall to window ratio"); actions are bare verbs ("Reset to default", "View", "Close"). Sentence case, with domain nouns capitalised as proper terms (Archetype, Space Use, Energy Flow Parameters, Site EUI, GFA, CFA, Plot Ratio). Help text is a fragment stating provenance ("from Archetype default"). Numbers: value in semibold ink, unit in tertiary grey, large numbers with lowercase k ("55.7k m²", "12.6 %"). Empty fields use named placeholders ("Untitled floor group", "Select", "Value"). Design-file placeholders use braces (`{Project name}`). No emoji, no exclamation marks, no marketing warmth. Domain terms: `references/principles/domain-glossary.md`.

## 4. Product principles (proposed by Claude 1 Oct 2026 — pending Pei Ning's sign-off)

Apply these as working rules. When a design decision hinges on one, name it ("P3") so it can be challenged. Each has a test you can run on a screen.

1. **Numbers you can trust.** Every metric shows unit, basis and confidence; no false precision, no invented benchmarks. *Test:* could a consultant put this number in front of a client and answer "where does it come from?" from the screen alone? **Caveat pattern:** short persistent qualifier by the value (`· upper bound`) + methodology behind an info tooltip.
2. **Show the provenance.** Every input says where it came from — measured (bills, BMS, survey), default (Archetype, Space Use), inferred (OSM, drawings) or user-entered — and the user can override any default. Retrofit work lives or dies on measured vs modelled. *Test:* pick any field; can you tell whether a human set it?
3. **Targets visibly drive the analysis.** Picking a target (e.g. Green Mark) changes what's on screen — pass/fail, gap to target, what to change. Clearing it is handled too. *Test:* switch the target; does anything on screen move?
4. **Component before data.** If a design problem is really a missing-data problem (e.g. parcel edges without human-readable identifiers), raise it early as an open question instead of designing around it. *Test:* is any label, option or default on this screen something the backend doesn't actually have?
5. **Dense, not cluttered.** Expert users want a lot on one screen: hierarchy, grouping, progressive disclosure (collapsible sections, Tooltip, FullScreenModalHeader views) — not removal. *Test:* squint — is there exactly one most important thing per panel?
6. **The model stays visible.** Panels never permanently cover what's being analysed; selection syncs between tree/panel and canvas. *Test:* select something in the panel; is it highlighted on the canvas (and back)?
7. **Comparable, reversible work.** Proposals behave like PRs (fork / rebase / merge): design for comparing (deltas vs baseline), reverting and seeing what changed. Nothing destructive without a confirm or an undo. *Test:* can the user get back to what they had five minutes ago?
8. **Long work never blocks.** Simulations and imports run in the background with honest progress; the user can leave, keep editing (results go stale, visibly) and come back. Anything that spends credits or runs long says so before it starts. *Test:* start a run, then try to do something else.
9. **One system, many products.** Urbanflow and Flux share the AppShell, Flow components, voice and vocabulary; a product-specific need is a new Flow component (flagged), not a local one-off. *Test:* would this screen look at home in the other product?

Patterns (metric cards, caveats, provenance, targets, runs, calibration, recommendations, compare, proposals, data import, parcel edges, onboarding) → `references/principles/patterns.md`.

## 5. Accessibility baseline

WCAG 2.2 AA; use `references/principles/contrast.md`, don't eyeball. Known DS gaps to flag once (the fix belongs in the DS, not only the screen): **tertiary ink (50%) = 3.19:1** — fails for the small unit labels and section headings that use it; placeholder 2.43 and disabled 1.90; caution text/icons on white; all stroke greys < 3:1 for input/checkbox boundaries; small-number badges and XS/S avatar initials are 9–10px. Keyboard: every action reachable with visible focus. Charts and canvas overlays: never colour alone.

## 6. Code ↔ design drift (flag, don't silently resolve)

Code (`@urbanflow/theme`) carries only Flow tokens, named mechanically from Figma (`Background/Default` → `bg-background-default`, `TextIcons/Primary` → `text-texticons-primary`, `header/large` → `text-header-large`). Verify the component registry status; shipped screens may use older app components; when a build differs from Flow, design to Flow and list the drift for eng. Mapping: `references/principles/tokens.md` §7.
